# Word documents

Use this guidance when a project task needs a `.docx` file. Work in the linked project folder and preserve any original file unless the user asks to replace it.

## Choose a workflow

- For a quick reading or summary, use `read_office` first.
- For a new document, write the content in a project Markdown file, review it, then use `convert_markdown_document` to export DOCX. This keeps the source editable and makes later revisions easier.
- For an existing document that needs detailed changes, inspect its structure before editing. If a suitable local document library or LibreOffice is available, use it to make a copy and apply the requested changes. If tooling cannot preserve features such as tracked changes, comments, or fields, explain the limitation before replacing those features.

## Quality checks

Check headings, tables, links, images, citations, and page breaks in the result. Confirm the output opens in a document viewer and that no requested content is missing. Keep temporary files outside the final deliverable folder.
